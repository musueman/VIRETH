# 비레스 소개페이지와 이야기 서고 통합 설계

## 목표

루나톡 캐릭터 `70170` 소개페이지와 `비레스 5083 이야기 서고`를 하나의 사용자 흐름으로 연결한다. 소개페이지는 대화 시작 방법을 설명하고, 이야기 서고는 선택한 시작 장면과 이어지는 기록을 읽는 역할을 맡는다.

## 확정 디자인

- 렌과 듀란은 같은 규격의 승인된 안내자 자산 쌍을 사용한다.
  - 렌: `assets/story-guides/ren-ending-guide.png`
  - 듀란: `assets/story-guides/duran-ending-guide.png`
- 두 인물은 소개페이지에서 비레스를 먼저 걷는 여행자이자 시각 안내자로만 표시한다.
- 기존 사고 안내, 비레스 소개 문장, 8개 시작 장면, 호출어와 최근 변경 내역은 보존한다.
- 이야기 서고의 14개 원문, 30개 삽화, 참고 설명과 슬라이더 코드는 수정하지 않는다.

## 통합 동선

소개페이지의 상단 독서 버튼은 기본 시작의 이야기 서고 화면으로 이동한다.

`https://vireth-starting-records.musueman.chatgpt.site/reader?v=24#scenario=gate-arrival`

각 시작 카드의 `이 시작과 이어지는 이야기 읽기` 링크는 다음 장면으로 직접 이동한다.

| 소개 카드 | 이야기 서고 장면 |
|---|---|
| START 01 | `gate-arrival` |
| START 02 | `gate-watch` |
| START 03 | `mercenary-contract` |
| START 04 | `held-cargo` |
| START 05 | `strange-tracks` |
| START 06 | `market-ledger` |
| START 07 | `ration-line` |
| START 08 | `harbor-dawn` |

루나톡 소개 조각 안에 이야기 서고 전체 앱을 복제하거나 iframe으로 삽입하지 않는다. 플랫폼 제약과 중복 유지보수를 피하면서도 사용자는 고른 시작 장면에서 바로 해당 기록 묶음을 읽을 수 있어야 한다.

## 반응형 배치

- 데스크톱에서는 렌과 듀란을 좌우 가장자리에 같은 표시 높이로 둔다.
- 두 자산은 원본 캔버스 크기가 같으므로 공통 높이와 `object-fit: contain`을 사용한다.
- 모바일에서는 두 인물을 문서 흐름 안의 안내자 전용 영역에 두고 같은 높이로 표시한다.
- 인물은 제목, 설명, 버튼을 가리지 않아야 한다.

## 검증

- 렌과 듀란의 URL이 승인된 `story-guides` 쌍과 정확히 일치한다.
- 상단 독서 CTA와 8개 카드 링크가 `reader?v=24#scenario=...` 형식을 사용한다.
- 장면 ID는 8개가 중복 없이 정해진 순서와 일치한다.
- 기존 8개 시작 이미지, 제목, 역할, 호출어와 공지 문구는 유지한다.
- 외부 링크는 `target="_blank"`와 `rel="noopener noreferrer"`를 유지한다.
- 데스크톱과 모바일에서 인물 비율, 글자 겹침, 빈 이미지와 가로 넘침을 확인한다.
